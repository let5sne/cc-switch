# Sub2API Companion 供应商收敛设计

日期：2026-07-29
状态：已确认

## 目标

将 CC Switch 定位为 Sub2API 的桌面配套工具：

- 保留 Claude Code、Claude Desktop、Codex、Gemini CLI、Grok Build、OpenCode、OpenClaw 和 Hermes 的现有客户端配置能力。
- “添加供应商”页面唯一内置供应商预设为本站 `Sub2API`。
- 保留“自定义配置”入口。
- 不展示官方模厂、第三方中转、聚合平台、赞助商或推荐供应商预设。
- 不删除用户已经保存的供应商和配置。

## 非目标

- 不在桌面端复制 Sub2API 的账号池、上游供应商、调度、计费、合规或管理后台。
- 不物理删除上游 CC Switch 的预设定义、图标、翻译和测试数据。
- 不改变现有数据库结构。
- 不重写本地代理、会话、MCP、Skills、托盘或同步功能。
- 不在源码、构建产物或日志中内置用户 API Key。

## 方案选择

采用展示层收敛：

1. 在独立配置中定义本站名称、站点地址和各客户端需要的协议配置。
2. 添加页面只向现有预设选择组件提供一个 Sub2API 条目。
3. 上游预设数组继续保留在源码中，但不进入本站版的添加页面。
4. “自定义配置”继续由现有组件固定展示。

不直接删除约 1.1 万行上游预设。这样可以避免每次同步 CC Switch 上游时反复解决大面积供应商数据冲突。

## 本站连接配置

单一站点源：

- 站点名称：`Sub2API`
- 服务根地址：`https://api.ai.let5see.xyz`
- OpenAI/Anthropic 兼容 API 根地址：`https://api.ai.let5see.xyz/v1`
- Gemini 原生 API 根地址：`https://api.ai.let5see.xyz/v1beta`

各客户端继续使用自身原生配置格式：

| 客户端 | 本站配置 |
| --- | --- |
| Claude Code | Anthropic 原生格式，服务根地址由客户端组成 `/v1/messages` |
| Claude Desktop | Anthropic 原生直连模式，使用本站服务根地址 |
| Codex | `openai_responses`，`base_url` 为本站 `/v1` |
| Grok Build | Responses 协议，`base_url` 为本站 `/v1` |
| Gemini CLI | Gemini 原生格式，使用本站 `/v1beta` |
| OpenCode | OpenAI 兼容格式，`baseURL` 为本站 `/v1` |
| OpenClaw | OpenAI 兼容格式，`baseUrl` 为本站 `/v1` |
| Hermes | OpenAI 兼容格式，`base_url` 为本站 `/v1` |

Codex 和 Grok Build 使用原生 Responses 直连，不为本站配置强制开启 CC Switch 本地格式转换。

## 用户流程

1. 用户在任意受支持客户端中点击“添加供应商”。
2. 页面只显示“自定义配置”和“Sub2API”。
3. 用户选择 Sub2API。
4. 表单自动填写该客户端对应的本站地址、协议和安全默认值。
5. 用户填写自己的 API Key；站点地址在普通表单中只读。
6. 保存前先请求本站健康接口，再使用 API Key 请求对应模型接口。
7. 健康和认证均通过后才保存，并沿用现有切换逻辑写入客户端 live 配置。

模型列表从本站动态读取，不在 CC Switch 中长期维护本站模型清单：

- Claude、Codex、Grok Build、OpenCode、OpenClaw、Hermes 使用 `/v1/models`。
- Gemini CLI 使用 `/v1beta/models`。

## 错误处理

- `/health` 不可达：提示本站暂不可用，不保存配置。
- 模型接口返回 `401` 或 `403`：提示 API Key 无效或无权限，不保存配置。
- 模型接口返回成功但无可用模型：提示当前 Key 未分配可用模型，不保存配置。
- 网络超时或响应格式错误：显示可重试错误，不自动改用其他供应商。
- 保存或 live 配置写入失败：沿用现有原子写入和错误反馈，不删除旧配置。
- 已有供应商始终保留；本次改造只影响新建页的预设可见性。

## 兼容性

- 现有数据库和 Provider ID 不迁移。
- 现有已保存的官方或第三方供应商仍可查看、编辑、切换和删除。
- 导入旧配置仍按现有逻辑执行。
- 自定义配置仍允许高级用户连接其他地址，但应用不会主动推荐任何外部供应商。
- 官方登录恢复不作为供应商预设展示；已有官方配置不受影响。

## 测试设计

留下最小但覆盖边界的检查：

1. 对每个受支持客户端断言添加页只有一个供应商预设：`Sub2API`。
2. 断言“自定义配置”入口仍存在。
3. 对每个客户端断言生成的地址和协议与上表一致。
4. 断言 Codex/Grok Build 的本站配置不要求本地路由接管。
5. 断言健康失败、认证失败和无模型时均不提交 Provider。
6. 断言已有第三方 Provider 仍可在供应商列表中显示和切换。
7. 运行 TypeScript 类型检查、相关 Vitest 用例和 Rust 相关定向测试。
8. 启动 Tauri 界面，检查添加页在至少一个宽屏和一个窄屏视口下无空白、溢出或残留推荐徽章。

## 验收标准

- 所有受支持客户端入口仍存在。
- 每个客户端的添加页只显示“自定义配置”和“Sub2API”。
- 页面不再显示任何外部供应商、推荐徽章或推广链接。
- 使用有效本站 API Key 可以保存并生成正确的客户端配置。
- 无效 Key、本站不可达或无模型时不会保存半成品配置。
- 旧供应商数据不丢失。
- 工作区测试、类型检查和受影响界面视觉验收通过。
